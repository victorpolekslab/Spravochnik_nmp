## Что можно проверить

- Общая авторизация login/resume/refresh/logout через loopback WSGI. В браузере access только в памяти; серверный refresh хранится в памяти одного процесса, cookie содержит непрозрачный случайный handle. Строгий Origin для POST, совпадение Host, Secure/HttpOnly/SameSite, лимит длины служебных заголовков, no-store. После перезапуска server cookie потребует нового входа. Решение рассчитано на одного worker, PID и origin.
- Приватный тестовый экран НМП получает публичный экземпляр теста без ответа, выдаёт UUID на открытие формы, сохраняет исходные ответы и версию. Черновик сохраняется только для того uid, который открыл тест. Сервер повторно связывает cookie и bearer при записи.
- Очередь шифрует снимки AES-GCM в IndexedDB с неэкспортируемым ключом и AAD uid/app, не содержит токенов. Оригинал тела сохраняется до полного ACK. Повторы с задержкой и бюджетом. Web Locks сериализует login, resume, refresh и отправку внутри origin/профиля. Ранний запрос refresh переиспользует текущий access в gateway. Старые и неподдерживающие WebView не получают fallback, который мог бы отправлять параллельные запросы.
- Экран терапевта из второй ветки проверяет только вход и выход. Итоговый экзамен ЭКГ и оценивание терапевта отсутствуют. Серверные ключи ответов не входят в ветки и клиентские файлы.

## Локальный запуск

Использовать только локальную YDB `/local` с синтетическими аккаунтами и приложенный комплект этапов 5–6 на PYTHONPATH. Для записи в отдельном чистом тестовом экземпляре нужен CREATE из точного DDL с nullable `answers_digest String` сразу в определении `test_attempts`. Production ALTER на этапе 7 не выполняется. Доступ тестовым uid выдаётся отдельно. Для ручного просмотра нужны активный подтверждённый тестовый аккаунт, app:use, learning:view и learning:submit. В тестах это делает fixture автоматически в изолированном экземпляре.

Указать `MEDICAL_YDB_LOCAL_PORT` и `MEDICAL_PILOT_CATALOG` (приватный абсолютный путь к 06_catalog_nmp.json). Установить пять независимых 32-байтных случайных ключей в base64, через `MEDICAL_PILOT_ACCESS_KEY`, `MEDICAL_PILOT_REFRESH_KEY`, `MEDICAL_PILOT_REGISTRATION_KEY`, `MEDICAL_PILOT_RECOVERY_KEY`, `MEDICAL_PILOT_DIGEST_KEY`. Для локального учебного пути явно задать `MEDICAL_PILOT_LEARNING=1`; по умолчанию он закрыт. Для второго экрана указать `MEDICAL_PILOT_THERAPIST_DIR` с каталогом интеграции из PR терапевта. Запуск:

```sh
PYTHONPATH="/path/stage5:/path/stage6" python integration/medical-platform/07_run_pilot.py
```

Открыть `http://localhost:8766/pilot/nmp` в браузере, который поддерживает Secure cookies на localhost и Web Locks. Этот запуск сервера допускается только на loopback. В реальном закрытом пилоте нужны TLS, управляемый ingress, распределённые квоты, серверное хранение сессий и безопасный ротационный keyring. IndexedDB защищает снимок при хранении, но скрипт того же origin и XSS имеют доступ к операции расшифровки. Общий origin с опубликованными сторонними ресурсами включать только после отдельной проверки.
