# Формат учебного курса (course.json), версия 1

Курсы для раздела «Обучение и опросы» готовит отдельный чат («редакция курсов»).
Он кладёт файл в ветку **`courses`** этого репозитория по пути `courses/<id>/course.json`.
Чат разработки забирает файл командой `tools/course/import_course.py`. Команда проверяет файл,
рисует слайды, озвучивает лекцию, встраивает курс в приложение и ставит его в ленту.

Порядок в чате разработки: `import_course.py fetch <id>` → `preview <id>` (слайды показать заказчику) →
`build <id>` (озвучка идёт примерно 1,3 минуты на минуту лекции — запускать в фоне) → проверка в приложении →
`git add courses media learn` + `tools/release_content.sh "Курс: …"`.

Ветка `courses` — только входящие. Сайт и приложение собираются из `main`, поэтому в `courses`
можно класть черновики без риска.

## Структура файла

```json
{
  "format": 1,
  "id": "migraine",
  "status": "ready",
  "title": "Мигрень",
  "sub": "клиника, дифдиагноз, купирование приступа",
  "src": "КР295_3",
  "srcName": "КР «Мигрень», Минздрав России, 2024 (ID 295_3, взрослые)",
  "course":  { "min": 7, "cards": [ ... ], "quiz": [ ... ] },
  "lecture": { "sub": "...", "srcName": "...", "slides": [ ... ], "quiz": [ ... ] },
  "feed":    { "course": "текст карточки в ленте", "lecture": "текст карточки в ленте" },
  "notes": "что важно знать разработчику (необязательно)"
}
```

| Поле | Обязательно | Что это |
|---|---|---|
| `format` | да | всегда `1` |
| `id` | да | латиница, цифры, `_`; 2–24 символа; совпадает с именем папки. Повтор id = обновление курса |
| `status` | да | `draft` — импортёр только проверит; `ready` — можно выпускать |
| `title`, `sub` | да | название и подзаголовок (до 80 символов) |
| `src` | нет | главная КР в виде `КР<ID>` (ID с cr.minzdrav.gov.ru, например `КР162_3`) |
| `srcName` | да | полная ссылка на источники для карточек |
| `course` | нет* | карточки + проверка |
| `lecture` | нет* | лекция со слайдами и озвучкой + тест |
| `feed` | да | по строке (до 200 символов) для каждой части, которая есть |

\* Должна быть хотя бы одна из двух частей.

## Часть «course»: карточки

`min` — сколько минут на прохождение. `cards` — 8–20 карточек:

```json
{ "k": "Клиника", "h": "Портрет болезни", "lead": "1–2 предложения (необязательно)", "blocks": [ ... ] }
```

`k` — короткая рубрика над заголовком, `h` — заголовок карточки. `blocks` — 1–4 блока. Это те же
блоки, что и в справочнике:

| `t` | Поля | Как выглядит |
|---|---|---|
| `targets` | `h`, `items[]` | цели: «после курса вы сможете…» |
| `exam` | `h`, `items[]`, `note?` | список с галочками: что проверить, признаки |
| `flags` | `h`, `items[]`, `note?` | красный блок: сигналы опасности |
| `warn` | `h`, `items[]` | перечёркнутый круг: чего не делать, что не рекомендовано |
| `steps` | `h`, `items[{s, note?}]` | нумерованный алгоритм |
| `scheme` | `h`, `items[{s, text}]` | лесенка шагов со стрелками (`s` — короткая метка) |
| `table` | `h`, `cols[]`, `rows[[]]`, `note?` | таблица; первая ячейка строки — заголовок строки |
| `rx` | `h`, `rows[]`, `note?` | препараты: `{n, d, note?, src?}` или «один из»: `{one, opts:[{n, d, note?, src?}]}` |
| `note` | `text` | серая заметка, 1–3 предложения |
| `fold` | `h`, `sub?`, `items[]` | раскрывающийся блок «подробнее»; в `items` можно `**жирный**` |

У любого блока может быть `src` (`КР<ID>`): под блоком появится ссылка на КР.

`quiz` — 5–8 вопросов (формат ниже).

## Часть «lecture»: слайды под голос

8–16 слайдов, всего 5–10 минут речи (синтез говорит около 125 слов в минуту, то есть 600–1250 слов на всю лекцию).
У каждого слайда есть макет `layout`, заголовок для списка слайдов `h`, текст озвучки `say` и,
при желании, сноска `src` (мелкий текст внизу слайда).

| `layout` | Поля | Для чего |
|---|---|---|
| `title` | `h`, `sub?`, `kicker?` | титульный слайд |
| `points` | `h`, `items[]` (до 6), `note?` | тезисы |
| `big` | `kicker?`, `value`, `text`, `items[]?` (до 3) | крупная цифра: «30,8 %», «1 из 3» |
| `compare` | `h`, `left{h, items[]}`, `right{h, items[]}`, `note?` | сравнение двух вещей |
| `table` | `h`, `cols[]` (2–3), `rows[[]]` (до 7) | дифдиагноз и т. п.; строка, первая ячейка которой начинается с `!`, выделяется красным |
| `flags` | `h`, `items[]` (до 14) | красные флаги в две колонки |
| `case` | `kicker` («Случай 1»), `h`, `facts[]` (до 6), `question?` | условие клинического случая |
| `answer` | `kicker`, `h`, `items[]` (до 5), `verdict` | разбор случая; `verdict` — итог жирным |
| `meme` | `kicker?`, `left{h, quote, foot?}`, `right{h, items[]?, punch}` | мем-сравнение: тёмная и светлая карточки |
| `end` | `h`, `items[]` (3–5) | итоговые правила, нумерованные |

В видимом тексте слайдов можно писать `**жирный**` и `==красный==`. На слайде — тезисы,
не полные предложения: до 12 слов в пункте.

### Текст озвучки `say` — пишется для уха, не для глаза

- 40–130 слов на слайд, короткие предложения.
- Числа словами и в нужном падеже: «у тридцати одного процента», «сто восемьдесят на сто двадцать».
- Без сокращений и латиницы: «головная боль напряжения», а не «ГБН»; «эс-пэ-о-два» не читается — пишите «сатурация».
- Без скобок, кавычек-«ёлочек», тире в роли знака минус, символов ≥ ≤ %.
- Первый слайд — вступление, последний — итог и переход к тесту.

## Вопросы теста (`quiz` в обеих частях)

```json
{ "q": "Вопрос", "o": ["вариант 1", "вариант 2", "вариант 3", "вариант 4"], "a": 1, "e": "разбор: почему верно" }
```

`a` — номер верного варианта, считая с нуля. Варианты — 3–4, правдоподобные; верный вариант
должен стоять на разных местах в разных вопросах. Разбор `e` — 1–2 предложения со ссылкой на КР.
Лучше всего работают вопросы-ситуации «пациент… что делать?».

## Правила содержания (договорённости с заказчиком)

- Аудитория — фельдшеры неотложной медицинской помощи (НМП), Тюменская область. Всё через призму вызова: узнать, не пропустить опасное, что сделать на месте, кого везти.
- Дозы — только из клинических рекомендаций Минздрава; если в КР дозы нет — «по инструкции».
- Применение вне инструкции помечать «#».
- В укладке НМП нет кислорода, тромболизиса и морфина — не предлагать их. Клопидогрел и гепарин есть.
- Стиль — тезисы, коротко. Мемы — добрые, про ситуации, без насмешек над пациентами.
- Каждая цифра и утверждение — с источником (КР, МКБ, крупные исследования); источники перечислить в `srcName`.

## Картинки и схемы

Файлы кладутся рядом с курсом: `courses/<id>/img/<файл>` — SVG (лучше всего), PNG, JPG или WebP, до 1,5 МБ.
Лучше всего подходит формат 16:9 (например, 960×540) на светлом фоне со своим заголовком внутри.
В SVG нельзя использовать скрипты, `foreignObject` и внешние ссылки: шрифты и всё остальное — внутри файла.

**На слайде** — поле `img`, например `"img": "img/s03_leads.svg"`, и при желании `imgMode`:
- `side` (по умолчанию) — текст слайда слева (около 40 %), схема справа. Подходит для схем с подписями.
- `full` — схема на весь слайд, сверху одна строка (`kicker` + `h`), снизу подпись из `caption`, `verdict`, `question` или `note`.
  Пункты и таблица слайда в этом режиме не показываются — их содержание должно звучать в `say`. Подходит для ЭКГ-лент и подробных схем.
- Отдельный макет `image`: `{h, img, caption?}` — схема на весь слайд.
- На макетах `title` и `meme` картинки не ставятся, на `compare` — только `full`.
- На слайде-условии (`case`) схема не должна подсказывать ответ — ответ показывайте на слайде `answer`.

**В карточке** — блок `{"t": "img", "img": "img/s04_electrodes.svg", "h": "заголовок?", "caption": "подпись?"}`.
По нажатию схема открывается крупно в браузере, где её можно увеличить. Без интернета вместо неё будет надпись «Схема не загрузилась».
